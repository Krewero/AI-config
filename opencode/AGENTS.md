# Global AGENTS.md (OpenCode)

## Purpose
Global baseline instructions for this OpenCode setup: workflow, safety, and how agents should behave across any repository. Project-specific conventions live in the repo-local AGENTS.md generated by `/init`. 

---

## Workflow (command-driven)
Use this command sequence as the default working loop:

1) `/init` → Project_Initializer
2) `/add-task <input>` → Task_Manager (input is $ARGUMENTS)
3) `/plan [T-NNNN]` → plan (writes `./plans/plan-<task-id>.md`)
4) `/build [T-NNNN]` → build (implements plan)
5) `/review` → Code_Reviewer (manual)
6) `/commit` → Repo_Manager (manual)

---

## Task system rules
- `tasks.yaml` is the source of truth for AI task state.
- Tasks represent AI-managed work; human work may exist in the repo but is not required to be represented as tasks.
- Task IDs are `T-NNNN` and always increment as `max + 1`.

---

## Safety boundaries
- Respect `dont_touch_paths`: do not propose or generate changes there without explicit approval.
- Respect `delegable: false`: do not implement; only propose/document.
- Never persist secrets or client-sensitive data in files, Beads, or long-term notes.

---

## Tooling policy
- MCP-first for inspection and metadata (Git/GitHub).
- Prefer diffs and explicit command blocks for any VCS actions; the user executes them. 
- If MCP tools are unavailable, fall back to bash only when allowed and keep it minimal.

---

## Review policy (important)
- Reviews are manual (`/review`).
- Code_Reviewer must separate:
  - AI-generated blockers (can REJECT)
  - User-written warnings (non-blocking)

---

## Beads policy
- Beads is AI-only persistence for in-flight tasks (DOING/BLOCKED).
- `tasks.yaml` remains authoritative; Beads is recovery support only.
