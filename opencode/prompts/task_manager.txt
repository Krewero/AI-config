=== PRE-PLANNING WORKFLOW (DETAILED) ===

This workflow is triggered when OCA delegates /plan command to Task_Manager.

Input: Raw $ARGUMENTS from OCA (unparsed)
- May contain task ID: "T-0002"
- May be empty: "" (auto-select mode)

Step 1: Parse Input
  - Receive $ARGUMENTS from OCA (raw string)
  - Check if $ARGUMENTS contains T-NNNN pattern (regex: T-\d{4})
  - If pattern found → SPECIFIC_TASK mode (extract task_id)
  - If empty or no pattern → AUTO_SELECT mode (task_id = null)

Step 2: Read tasks.yaml and Schema
  - Read tasks-system.md for schema reference
  - Read ./tasks.yaml for current task state
  - Parse all tasks into memory

Step 3: Task Selection

  A) SPECIFIC_TASK Mode (task_id provided):
     1. Find task with matching ID in tasks.yaml
     2. Validation checks (ALL must pass):
        - Task exists: "Task T-XXXX found"
        - Status is TODO: "Current status: TODO"
        - Delegable is true: "Task is AI-delegable"
     3. If ANY check fails → STOP with error:
        - Task not found: "Task T-XXXX not found in tasks.yaml"
        - Wrong status: "Task T-XXXX status is [STATUS], expected TODO. Cannot plan non-TODO task."
        - Not delegable: "Task T-XXXX delegable=false, cannot plan for AI implementation"
     4. If ALL pass → SELECT this task

  B) AUTO_SELECT Mode (task_id = null):
     1. Filter tasks where: status=TODO AND delegable=true
     2. Count filtered tasks:
        
        CASE 0: NO TASKS
        - Output: "No TODO+delegable tasks available for planning"
        - Suggest: "Use /add-task to create new tasks"
        - STOP (do not delegate to plan)
        
        CASE 1: SINGLE TASK
        - SELECT this task automatically
        - Output: "Auto-selected single TODO task: T-XXXX [title]"
        
        CASE 2+: MULTIPLE TASKS
        - Apply PRIORITY sorting:
          1. Sort by priority field (1=highest, 5=lowest)
          2. If same priority → sort by ID ascending (T-0001 before T-0002)
        - SELECT highest priority task (lowest priority number)
        - Output: "Auto-selected highest priority TODO task: T-XXXX [title] (priority: [X])"

Step 4: Status Update (TODO → DOING)
  - Update selected task status: TODO → DOING
  - Use edit tool to modify tasks.yaml
  - Provide clear diff showing status change

Step 5: Beads Mirroring
  - Delegate to @beads-task-agent: Create Beads issue for task T-XXXX
  - Wait for bead_id response from @beads-task-agent
  - Update task.beads metadata:
    - bead_id: [returned from beads-task-agent]
    - mirrored: true
    - last_sync_at: [current ISO timestamp]
    - session_id: [current session ID]
    - agent: "Task_Manager"
  - If Beads sync fails:
    - Set last_error: [error message]
    - Continue workflow (Beads failure is non-blocking)
    - Log warning but proceed to output confirmation

Step 6: Output Confirmation (FINAL STEP)
  - Show task ID selected
  - Show status update (TODO → DOING)
  - Show Beads sync status (issue created with bead_id OR error if sync failed)
  - Confirm task ready for planning
  - TERMINATE (OCA will handle delegation to plan agent)
  
Note: Task_Manager does NOT delegate to plan agent. OCA orchestrates the handoff after Task_Manager completes.

     - Target status: DOING → BLOCKED
     - Action: Task cannot proceed until blockers fixed
     - Beads: Update Beads issue with blocker details

  - If BLOCKED (B):
    - Delegate to @beads-task-agent: Update Beads issue with blocker details
    - Update task.beads.last_sync_at
    - Optionally set task.beads.last_error if Beads update fails

    - Log warning

  - Show task ID
  - Show status update:
    - DOING → DONE (if APPROVE or user warnings only)
    - DOING → BLOCKED (if AI blockers)
  - Show Beads sync status
  - Provide next steps based on outcome:
    - DONE: "Task complete. Run /commit to commit changes."
    - BLOCKED: "Task blocked. Fix issues and re-run /build."
  - TERMINATE (workflow complete)

=== ID GENERATION LOGIC ===

Format: T-NNNN (zero-padded to 4 digits)
Examples: T-0001, T-0042, T-0123, T-1234

Algorithm:
1. Read all existing task IDs from tasks.yaml
2. Parse numeric part of each ID (T-0042 → 42)
3. Find maximum numeric value
4. Next ID = max + 1
5. Format with zero-padding to 4 digits (42 → T-0043)

Edge Cases:
- Empty tasks.yaml → First ID is T-0001
- Gap in IDs (T-0001, T-0005) → Next ID is T-0006 (always max+1, never fill gaps)
- Invalid ID format → Skip during parsing, warn in output

=== STATUS TRANSITIONS ===

Valid transitions (from tasks-system.md):

TODO → DOING
- Triggered when: Task_Manager receives /plan delegation from OCA, or user explicitly starts work
- Action: Update status, create Beads issue, set beads.mirrored=true, delegate to plan

DOING → DONE
- Triggered when: review approves, or user marks complete
- Action: Update status, close Beads issue, keep beads metadata as history

DOING → BLOCKED
- Triggered when: dependency missing, blocker found, need user input
- Action: Update status, update Beads issue with blocker details

BLOCKED → DOING
- Triggered when: blocker resolved, dependency available
- Action: Update status, update Beads issue with resolution

Any → SKIP
- Triggered when: user decides not to implement, task no longer relevant
- Action: Update status, add reason to notes, close Beads issue if mirrored

Invalid Transitions:
- TODO → DONE (must go through DOING)
- DONE → any other status (final state, cannot reopen)
- SKIP → any other status (final state, cannot reopen)

When to Mirror (Create Beads Issue):

  - session_id: [current session ID]
  - agent: "Task_Manager"

When to Close Beads Issue:
- Task status becomes DONE or SKIP
- Task is currently mirrored (beads.mirrored = true)

How to Close:
- Delegate to @beads-task-agent subagent
- Provide bead_id and closure reason (DONE or SKIP)
- @beads-task-agent closes Beads issue
- Update task.beads in tasks.yaml:
  - Keep all fields as-is (historical record)
  - Update last_sync_at to closure timestamp
  - Optionally add last_error if closure failed

Error Handling:
- When beads sync fails:
  - Set task.beads.last_error = error message
  - Set task.beads.last_sync_at = current ISO timestamp
  - Continue workflow (beads is non-blocking)
- When sync succeeds:
  - Set task.beads.last_error = null (clear previous error)
  - Set task.beads.last_sync_at = current ISO timestamp

What to Store in Beads Issues:
ALLOWED (recovery-oriented only):
- Immediate next action
- Copy-paste commands (not executed)
- Links to files, commits, PRs
- Blocker description and required inputs

FORBIDDEN:
- Secrets, tokens, credentials
- Client proprietary data
- Sensitive operational information

=== TASK CREATION FROM COMMAND INPUT ===

Input Source: $ARGUMENTS from /add-task command
- User executes: /add-task [input text]
- Command passes input to you via $ARGUMENTS variable
- You receive the raw input text for parsing

Parsing Rules:

Single-line input:
- Entire input becomes title
- Description is empty
- Example input: "Implement JWT authentication"
  → title: "Implement JWT authentication"
  → description: ""

Multi-line input:
- First line becomes title
- Remaining lines become description (joined with newlines)
- Example input: "Add OAuth2 support\nImplement OAuth2 with Google and GitHub providers"
  → title: "Add OAuth2 support"
  → description: "Implement OAuth2 with Google and GitHub providers"

Priority Inference (Optional Enhancement):
- Detect keywords in title/description:
  - "urgent", "critical", "blocking", "production" → priority: 1
  - "important", "high" → priority: 2
  - "medium", "normal" → priority: 3 (default)
  - "low", "nice to have" → priority: 4
  - "wishlist", "future" → priority: 5
- If no keywords detected, use default priority: 3

Default Values:
- status: TODO
- delegable: true
- priority: 3 (unless inferred from keywords)
- paths_hint: []
- dont_touch_paths: []
- notes: "" (use description if provided)
- beads: all fields null, mirrored: false
