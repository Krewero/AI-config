=== ID GENERATION LOGIC ===

Format: T-NNNN (zero-padded to 4 digits)
Examples: T-0001, T-0042, T-0123, T-1234

Algorithm:
1. Read all existing task IDs from tasks.yaml
2. Parse numeric part of each ID (T-0042 → 42)
3. Find maximum numeric value
4. Next ID = max + 1
5. Format with zero-padding to 4 digits (42 → T-0043)

Edge Cases:
- Empty tasks.yaml → First ID is T-0001
- Gap in IDs (T-0001, T-0005) → Next ID is T-0006 (always max+1, never fill gaps)
- Invalid ID format → Skip during parsing, warn in output

=== STATUS TRANSITIONS ===

Valid transitions (from tasks-system.md):

TODO → DOING
- Triggered when: plan agent starts planning, or user explicitly starts work
- Action: Update status, create Beads issue, set beads.mirrored=true

DOING → DONE
- Triggered when: review approves, or user marks complete
- Action: Update status, close Beads issue, keep beads metadata as history

DOING → BLOCKED
- Triggered when: dependency missing, blocker found, need user input
- Action: Update status, update Beads issue with blocker details

BLOCKED → DOING
- Triggered when: blocker resolved, dependency available
- Action: Update status, update Beads issue with resolution

Any → SKIP
- Triggered when: user decides not to implement, task no longer relevant
- Action: Update status, add reason to notes, close Beads issue if mirrored

Invalid Transitions:
- TODO → DONE (must go through DOING)
- DONE → any other status (final state, cannot reopen)
- SKIP → any other status (final state, cannot reopen)

=== TASK CREATION FROM COMMAND INPUT ===

Input Source: $ARGUMENTS from /add-task command
- User executes: /add-task [input text]
- Command passes input to you via $ARGUMENTS variable
- You receive the raw input text for parsing

Parsing Rules:

Single-line input:
- Entire input becomes title
- Description is empty
- Example input: "Implement JWT authentication"
  → title: "Implement JWT authentication"
  → description: ""

Multi-line input:
- First line becomes title
- Remaining lines become description (joined with newlines)
- Example input: "Add OAuth2 support\nImplement OAuth2 with Google and GitHub providers"
  → title: "Add OAuth2 support"
  → description: "Implement OAuth2 with Google and GitHub providers"

Title Formatting:
- Keep imperative form (Implement, Add, Fix, Create, Update, etc.)
- Trim leading/trailing whitespace
- Max ~80 characters (if longer, truncate and move excess to description)
- Capitalize first letter

Description Formatting:
- Can be empty (single-line input)
- If multi-line, join all lines after first with newline separators
- Trim leading/trailing whitespace from each line
- Preserve user's formatting

Default Field Values:
- status: TODO
- delegable: true
- priority: 3 (medium)
- paths_hint: [] (empty array)
- dont_touch_paths: [] (empty array)
- notes: "" (empty string)
- beads: all fields null, mirrored: false

Optional Field Inference from Input Keywords:
- If input contains "urgent", "critical", "bug", "hotfix" → priority: 2 (high)
- If input contains "blocker", "blocking" → priority: 1 (highest)
- If input contains "nice to have", "optional", "enhancement" → priority: 4 (low)
- If input contains "manual only", "human required", "review needed" → delegable: false
- Otherwise use defaults

Parsing Examples:

Input: "Implement JWT authentication"
Output:
- title: "Implement JWT authentication"
- description: ""
- priority: 3
- delegable: true

Input: "Fix critical payment processing bug"
Output:
- title: "Fix critical payment processing bug"
- description: ""
- priority: 2 (inferred from "critical" + "bug")
- delegable: true

Input: "Add OAuth2 support\nImplement OAuth2 authentication with Google and GitHub providers using Spring Security OAuth2 client"
Output:
- title: "Add OAuth2 support"
- description: "Implement OAuth2 authentication with Google and GitHub providers using Spring Security OAuth2 client"
- priority: 3
- delegable: true

Input: "Setup production monitoring - manual only, requires DevOps approval"
Output:
- title: "Setup production monitoring"
- description: "Requires DevOps approval"
- priority: 3
- delegable: false (inferred from "manual only")

Input: "Urgent: Fix database connection pool exhaustion blocking all requests"
Output:
- title: "Fix database connection pool exhaustion"
- description: "Blocking all requests"
- priority: 1 (inferred from "urgent" + "blocking")
- delegable: true
